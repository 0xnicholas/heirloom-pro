# PROTOTYPE — 工作台界面外形（票 #21 反应物）

> **一次性产物，非交付代码。** 本目录回答一个问题：**这个界面能不能撑起一场投影工作坊？**

## 运行

```bash
open prototype/workbench-ui/index.html
```

（浏览器直接打开本文件即可；`?variant=A|B|C` 切换或用底部浮动条 / ←→ 键。）

## 三个变体（结构迥异，不是换肤）

| 变体 | 结构 | 投影场景假设 |
|---|---|---|
| **A — 步进三幕** | 顶部幕轨道（身份→织网→动词→草稿），全屏一次只看一幕，大字号表格/问句 | 房间注意力单点：逐词过堂，顾问驾驶，客户喊答案 |
| **B — 工作台三区** | 左术语池（单池双道）+ 中判定向导卡 + 右本体图/预检常驻；草稿右侧滑出 | 一切常驻不打断：词随时补、图随时看，问答与全局并进 |
| **C — 画布优先** | 暗色词汇流侧栏 + 中央注册表派生图谱（点击开节点详情）；草稿底部抽屉 | 图谱即谈话焦点：节点边指边点，词与图互相印证 |

三核心功能（倒词采集 / 判定向导 / 草稿+两层预检）每变体都齐，位置与呈现各不相同。数据为硬编码 HR 域示例（对齐归档原型本体），含 #20 决议的红黄绿灯草稿卡与「同名≠改名」红灯样例。

## 请针对这些点反应

1. **总壳**：投影工作坊的主形态选哪个？（常见答案：「B 的布局 + A 的字号」这类混搭——正中下怀）
2. **倒词**：快速输入 + 名/动/待定轻标记的节奏对吗？（变体 A 里在幕一，B 在左栏，C 在暗色流）
3. **判定向导**：问句措辞、选项封闭度、话术三句的位置——客户听得懂吗？
4. **本体图**：B 的右栏小图 vs C 的中央大图，图谱在工作坊里该是主角还是配角？
5. **草稿预览**：变更卡+红绿灯为主层、代码折叠为次层、「可贴回」按钮被红灯锁死——这个双层够不够撑客户确认环节？
6. **密度与字号**：投影可读性（3 米外）还差什么？

## 已知的原型简化（勿反应这些）

- 无工作簿持久化（会话管理仍是雾）；图布局硬编码；无 Prettier/bun 真调用（草稿为静态样例）。
