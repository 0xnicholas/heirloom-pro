> **范围**：DSL 工程形态、push 流程与权威态、变更分类学（三档矩阵）、status 生命周期、兼容口径与联动校验。

> **素材**：[ADR-0007](../adr/0007-ontology-evolution.md)（#6 决议全文）；CLI push 传输机制 ADR-0005 决议 7。

> **验收线**：深规格（[#13](https://github.com/0xnicholas/heirloom-pro/issues/13) 决议：逐端点表、逐条规范性陈述、示例内嵌、总表归附录）

## 决议要点（ADR-0007 播要）

1. **权威模型**：CLI 求值本体模块 → 定义 JSON → 全量期望态 PUT；服务端权威（当前定义 + revision + push 审计）；no-op 不涨 revision。
2. **收敛**：diff → 三档分类 → DDL+元数据+校验，Postgres 事务性 DDL 单事务全成全败。
3. **变更三档矩阵**（正文须全量铺开）：自动 / 数据校验 / 拒绝，逐条列变更类型与处置；拒绝信息**必须**给出路建议。
4. **无迁移语言**：拒绝档出路 = 一次性动作 / 接入端点重灌 / 外部同步器；无 `--allow-data-loss`。
5. **status = 纯元数据**：三值、默认 active、运行时零强制、无广播机器。
6. **push 联动校验 fail-closed**：谓词/动作/queryFn 引用悬空 → 整 push 拒绝；本体+动作+函数同 registry 同事务。
7. **兼容口径**：SDK 同源编译不签发；breaking = 拒绝档清单（公开）；自动档向后兼容；无版本协商。
